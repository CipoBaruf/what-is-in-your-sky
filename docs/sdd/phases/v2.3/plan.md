### 2.38 v2.3 decisions (2026-10-19)

The phase changes one thing on screen (F-98) and otherwise renames what is there.
Its decisions are how the sheet and the primitives are laid out so that the tests can read them, what the literals test matches and exempts, where the dev page lives so that it is served and never built, and why the eight tasks run one at a time.
SPEC §5.11 is adopted except where a row below says otherwise.

- **D-700 — The sheet is sections the tests parse; night is a colour set the test compares.**
  (FR-DS-1, FR-THEME-1 as amended; V23-3.) `tokens.css` is re-cut under seven markers, `/* == grid == */`, `space`, `type`, `edges`, `layers`, `colour`, and the `[data-theme='night']` block, in that order; `scripts/contrast.ts`'s `readTokens` gains `readSections(css)`, which returns each section's tokens in order, and the guide and both style tests read the sheet through it rather than by their own regexes.

  The type ladder keeps every size-and-line-height pair in use at `ed8748a` — six rem sizes above `--small` (2, 1.5, 1.375, 1.25, 1.125 and 1 rem) on five line heights (2.375, 1.75, 1.625, 1.125 rem and 1) — as `--text-<role>` / `--text-<role>-row` pairs named for the role of the element that uses them (`title`, `tagline`, `heading`, `lead`, `body`, …), never for the size, so a later collapse (OQ-37) is a value change and not a rename; the sheet task picks the roles from where each pair is used and records the table in its decision block.

- **D-701 — The literals test: what it matches, what it exempts, and how the allow-list only falls.**
  (FR-DS-2; V23-7.) `tests/styles/literals.test.ts` walks `src/**/*.css` except `tokens.css`, strips comments, and matches: a hex, `rgb(`, `hsl(`, `color-mix(` with a literal inside, or a CSS named colour other than `transparent`, `currentColor` and `inherit`; a `px`, `rem` or `em` number other than `0` **outside an `@media` or `@container` condition** (those are `breakpoint.test.ts`'s, D-702); `z-index:` followed by a digit; `outline` other than `outline-offset: var(--focus-offset-tight)`; `font-family:` whose value is not `var(--font-mono)`; and `content:` of `"[ "` or `" ]"` in a file outside `ui/components/primitives/`.
  For `src/ui/**/*.tsx` it matches `style={{ … }}` objects whose values are a colour or a length literal; a custom property (`'--x': …`) and a number computed at runtime are allowed, which is what the eleven inline styles at `ed8748a` set.
  `tests/styles/literals.allow.json` is `{ "<path>": { "count": n, "reason": "…" } }`, keyed by file so two tasks lowering two files touch two lines; the test fails when a file's matches exceed its count **and when they fall short of it**, so lowering a count is part of the change that earns it, and an entry at zero is a failure (it must be removed).
  The sheet task seeds the file at the day's counts and every later task lowers its own files; `R110` asserts the file is empty but for the entries the phase names (the chart modules' runtime geometry, if any remain) with their reasons.
- **D-702 — Breakpoints stay pixel literals in the modules and constants in `layout.ts`; the test is the join.**
  (FR-DS-3; V23-9, V23-10.) CSS cannot read a TypeScript constant, so every `@media` and `@container` condition keeps its number in the module as today, and `tests/styles/breakpoint.test.ts` holds each to an export of `lib/layout.ts`: the existing widths, the three heights `SIDEWAYS_MAX_HEIGHT_PX` (500), `SHORT_MAX_HEIGHT_PX` (700) and `WIDE_SHORT_MAX_HEIGHT_PX` (720), and `FRAME_LEGEND_MIN_CELLS` (62, `ChartFrame.module.css`'s container query, D-259).
  The test gains a syntax rule — every condition is `(width >= …)`, `(width <= …)`, `(height <= …)` or `(min-width: …ch)` in a container query — and a listing: it collects every condition in the tree as `(feature, comparator, value)` and compares the set to a committed list, `tests/styles/breakpoints.json`, so the rewrite to range syntax is proved to change no size by the list being identical before and after (the sheet task commits the list first, rewrites, and the test stays green).
  The floor this sets, Safari 16.4 / Chrome 104 / Firefox 63, is written in §11 and in `docs/DESIGN.md`'s rules; nothing in the tree targets anything older.
- **D-703 — A primitive is one `.tsx`, one `.module.css` and one manifest row; the manifest is the join between the guide, the dev page and the test.**
  (FR-DS-4, FR-DS-6; V23-4, V23-6.) `src/ui/components/primitives/` holds `TextButton`, `BracketLink`, `OptionToggle` and `ToggleGroup`, `Card`, `Rule` and `SectionHeading`, `Line`, `Field`, `Stack`, `Cluster` and `VisuallyHidden` — `OptionToggle` and `SectionHeading` move there from `common/` with their tests, their imports updated in the same task.
  `manifest.ts` exports `PRIMITIVES: readonly PrimitiveEntry[]` with `name`, `file`, `props` (name, type as a string, one sentence) and `when` (one sentence on when it is the right one); `primitives/manifest.test.ts` asserts every `.tsx` in the directory but the manifest and the tests has a row and every row a file, and that each row's `props` match the component's exported `Props` type by name (a type-level check: each entry's `props` is typed as `(keyof XProps)[]`).
  Primitives are leaves: an ESLint zone forbids `src/ui/components/primitives` importing `src/state`, `src/lib`, `src/i18n`, `src/data` and any other `src/ui/**` directory, so a primitive carries no copy and no behaviour of the app, only props.
  A feature component composes them and keeps its file and its name (`FailureLine` renders a `Line`, `PassCard` a `Card`, `SortToggle` a `ToggleGroup`, `CoordsInput` a `Field`), which is what keeps `controlRows.test.ts`, the component tests and the captures unchanged.
